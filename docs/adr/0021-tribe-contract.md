# ADR 0021 · Tribe contract: a tribe is an adapter with declared capabilities, a theme entry and the owner's own account

- Status: accepted · 2026-11-06
- Amends: [ADR 0006](0006-runner-adapter-behind-agentrunner.md) (adapters may also be owner files), [ADR 0018](0018-gemini-tribe-on-antigravity-cli.md) (the Gemini runner is chosen by `tribes[].adapter`)
- Related: [implementation-plan.md](../implementation-plan.md) §3.7, §3.14, §9.1 items 24–28; [product plan 0.8](../ke-hoach-dung-elvaria-0.8.md) §8; [kingdom.schema.json](../schemas/kingdom.schema.json)

## Context

Product plan 0.6 loosens principle 6 to "one account of the owner per tribe" and asks that a new provider (Codex, a raw API later) be added by the owner with an adapter, a theme entry and their own login, without touching the core. Until now the schemas hard-coded two tribes (`provider: claude | gemini`, `kingdom.tools.{claude,gemini}`, `mana.tribes.{claude,gemini}`).

## Decision

- `kingdom.tribes[]` replaces `tools` and `mana.tribes`: `{id, adapter, enabled, max_concurrent, tool?, pools?, budget?}`. `tribe` is an open id everywhere (`character.tribe`, `class.default_tribe`, `wake`, `mana.level`); `provider` is retired as an identifier.
- An adapter is either a package in this repo (`claude_code`, `antigravity`, `gemini_cli`, `codex_cli`) or an owner file `<kingdom>/adapters/<name>.mjs` exporting `createAdapter(kit)`. `kit` is injected by runner-core (prompt, tool policy, plot, normalisation, redaction, spawn and kill), so the file imports nothing. Only `apps/cli` loads adapters. (Amended 2026-11-09, P1-19, as the owner decided: the kit carries what an adapter does itself — spawn and kill tree, the minimal env, the run's context and `policy.json`, files of the run, the run log and redacted output, the letter's question, the tool fences; the prompt, the tool policy and the plot arrive in each `SpawnRequest`, and the CLI's own stream is the adapter's to read.)
- Every adapter declares `capabilities`: `headless` and `context_file` (required; context falls back to the prompt), `events`, `tool_gate`, `usage`, `structured_output` (should have), `resume`/`compact`, `subagent` (optional). The pure function `tribeLimitsOf(caps)` narrows a tribe that lacks one, as the product plan's table says: no `tool_gate` ⇒ ranks F–D only and no `read_before_write` zones; no `usage` ⇒ time-based mana and time breakers only; no `events` ⇒ working/done only and no apprentices. (Amended 2026-11-09, P1-19, as the owner decided after P0-11: the sign-ins an adapter runs with are a declared capability too, `capabilities.auth`, a non-empty list of `login` / `api_key`; `checkTribeAuth` holds `tribes[].tool.auth` to it in `elvaria doctor` and `elvaria tribe check`, so TribeSchema no longer names `gemini_cli`.) (Amended 2026-11-10, P1-40: an adapter may declare `capabilities.shell`, the shell its command tool runs in per OS, and the prompt names the one for the Steward's OS; optional, declared only where it was measured, so older adapter files still pass the conformance suite.) (Amended 2026-11-11, P1-53: an adapter may declare `capabilities.search: false` when its CLI has no search tool of its own; the core then gives a class with Glob or Grep git's read-only `git grep` and `git ls-files` on a git plot, and the hook refuses their options that run a program or reach past the tracked files; optional, absent means the CLI searches itself. The command list stays in the core, not the adapter, because the hook must know each command's dangerous options.) (Amended 2026-11-12, PS-21, [ADR 0029](0029-code-graph-of-the-territory.md): the code graph's read-only commands, `graphify query`, `path`, `explain`, `affected`, go the same way beside the search commands: the core grants them (ToolPolicy `graph_commands`) to a class with Glob or Grep that does not deny a bare `Bash` when the quest's graph is built, and each adapter turns them into its CLI's rules, the shell tool with these rules alone for a Claude class without one; no new capability.)
- Every adapter must pass the conformance suite in runner-core (`elvaria tribe check`) before it can be enabled.
- A character's tribe is fixed for life, like its class: reputation and scripture belong to that tribe's models. Adding a tribe means summoning new characters; existing characters, quests and data do not change.
- Codex: a full-tier candidate (`codex exec --json`, AGENTS.md, lifecycle hooks trusted by hash, `--output-schema`, `exec resume`). Its adapter is optional task P1-12d and starts with a spike; generated hook files must be byte-stable so the owner trusts them once. (Amended 2026-11-12, P1-12d, as the owner chose: Codex 0.167 keeps hook trust in the owner's `config.toml`, which a session must not load, and skips an untrusted hook without a word; so each session passes `--dangerously-bypass-hook-trust`, and only after `codex app-server`'s `hooks/list` for the plot, 0 mana, shows that every hook Codex would run is one of Elvaria's own, as given. A hook of the owner's, a plugin's or a project's refuses the session.)
- (Amended 2026-11-12, as the owner decided) The list of tribes stays open past Codex: Grok, Cursor, Kiro or any later CLI is added by the same steps, with no change to the core. What the core still knows per CLI becomes data an adapter declares: the models it serves with the maker family of each (a model of unknown family never counts as another family, ADR 0008), and its hook payload, read through a neutral dialect. Task PS-23, after the Codex adapter shows what a third CLI needs.

## Consequences

- Separation of duties gains pairs as tribes are added (Codex is model family `gpt`), and one sleeping tribe stalls less work.
- A tribe without a theme entry shows a neutral crest until the theme has one. (Amended 2026-11-12, as the owner decided, task PS-24: a tribe must be told apart at a glance, so a tribe without a theme entry gets a look drawn from the theme's pool by its id, the same on every run and never shared with another tribe; the owner may choose one instead.) (Amended 2026-11-13, PS-24: a look is a set of parts, palette, crest, figure, aura and portrait frame, each an id of the theme's look pool, with a name; the pool is theme data with a schema of its own, and the fantasy pool ships inside the domain, the one package both the CLI and the UI import. The owner's choice is `kingdom.tribes[].look`, written whole by `elvaria tribe look`, and wins over the pinned entry; the draw walks the pool in the order of `kingdom.tribes[]` and never takes a palette or crest that is pinned or chosen, so adding a tribe changes no other look. Display only, as ADR 0025 says of persona.)
- An owner adapter file runs with the owner's rights; it still goes through the core's tool policy, minimal env and redaction.
