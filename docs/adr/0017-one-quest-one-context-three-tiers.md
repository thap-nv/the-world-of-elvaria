# ADR 0017 · One quest, one context: three execution tiers (script, apprentice, session); revival starts a fresh session from the handover letter

- Status: accepted · 2026-11-06 · updated 2026-11-06 with spike P1-02 (Claude Code 2.1.318) · amended 2026-11-07 (resume after an answer; its prompt, P1-05) · amended 2026-11-13 (split by the peak context, PS-06)
- Related: [implementation-plan.md](../implementation-plan.md) §3.5, §3.11, §3.12, §9.1 items 14–16; [spike P1-02](../spikes/claude-2026-11.md)

## Context

Principle 13 ([product plan 0.8](../ke-hoach-dung-elvaria-0.8.md)): every character is a new top-level session that loads only what it needs from the journal, scripture and gazetteer; long memory lives on disk; the Chancellor splits work so one quest fits one context; what a machine can do does not call a model. The product plan (§7, "Script, sub-agent hay phiên mới") defines three tiers.

Spike P1-02: under `-p`, an agent from `--agents <file>` gets exactly its `tools`, runs on its `model` (counted in the session's `modelUsage`) and stops at `maxTurns`. But the parent can resume a stopped agent with `SendMessage` for more turns; an allow rule for `Agent(apprentice)` does not stop other agent types; a `SubagentStart` hook that exits 2 does not block; `SubagentStop` does not fire when `maxTurns` stops the agent. A deny rule `Agent(<type>)` and a `PreToolUse` hook on the `Agent` tool both block.

## Decision

- **Script** (`quest.tier = script`): only from `registry/scripts.json`. The Steward runs `node registry/scripts/<id>.mjs` in the plot; no model, no secret, mana 0; verdict by `machine`. A script error goes to `infirmary`.
- **Apprentice** (sub-agent inside a session): Claude gets `--agents <run_dir>/agents.json` defining exactly one `apprentice` (`maxTurns = breakers.subagent_max_turns`, default 30; tools a subset of the class; cheap model; no `Agent` tool). A `PreToolUse` hook on the `Agent` tool blocks every `subagent_type` other than `apprentice`, and `permissions.deny` lists the built-in types (`Explore`, `general-purpose`, `Plan`, `statusline-setup`) as a second fence. The character's `--tools` has no `SendMessage`, so a stopped apprentice cannot be resumed past its `maxTurns`. (Amended 2026-11-06, P1-02, confirmed by the owner; implementation-plan §11. Before: `Agent(*)` denied except `Agent(apprentice)`, and a `SubagentStart` hook blocking.)
- `subagent_max_minutes` (default 5) is measured from the stream's `system/task_started` to `system/task_updated` (`status`, `end_time`; `task_progress` carries `duration_ms`), because `SubagentStop` misses the `maxTurns` stop; overrun → `agent.subagent.overrun`, charged to the parent's breakers. It is not a kill switch: a sub-agent cannot be killed from outside. (Amended 2026-11-06, P1-02, confirmed by the owner.)
- Antigravity sub-agents are denied until spike P1-12a shows how to bound them.
- **Session**: a new top-level session per quest or child quest, spawned by the Steward.
- Invariants: a verifier is never a sub-agent of the doer; sub-agents do not spawn sub-agents; over-threshold work stops and becomes a child quest.
- Revival after mana or a crash is a **fresh session** whose prompt is the quest + `handover.md` + the last 20 lines of `journal.jsonl` + the branch's `git log` and diff. `--resume <session_id>` only when `dispatch.resume_after_mana = true` (default false; `--settings` is passed again). (Amended 2026-11-07, owner, before P1-01: also when the owner answers a character's question within `dispatch.resume_after_answer_minutes` of `blocked.asked_at` (default 55, `null` turns it off) and the adapter declares `resume`, because the session's context, and likely its prompt cache, is still worth more than a re-read; a later answer starts a fresh session whose handover carries the answer. Implementation-plan §2.4, P1-05.) (Amended 2026-11-07, P1-05, confirmed by the owner: a resumed session's prompt carries only what is new — that it goes on, and the owner's answer when there is one — since the CLI session still holds the quest and the letter; the minutes count to the moment the session opens.)
- The Chancellor sets `tier`, batches tiny tasks into one quest (often `batch` with `units[]`), and splits work whose `estimate.tokens` exceeds `breakers.context_budget_tokens` (default 120 000) into a parent `plan` quest and children. (Amended 2026-11-13, PS-06, the owner's choice in the session, awaiting settlement in implementation-plan §11: a session costs roughly its turns times its context, and the token breaker counts cached reads at a tenth (P1-23), so `estimate.tokens` of a rank D job on a web repository is some 250 000 and the old rule split nearly every honest draft. A draft now gives its peak context, `estimate.context`, and the work is split when that passes the budget; a draft without it stands on `estimate.tokens` as before. The quest keeps tokens and minutes only. A mage's sub-quest whose given peak passes the budget fails the plan's `subquests` check.)

## Consequences

- `docs/tier-report.md`, generated from the event log, shows tokens per quest and per tier for tuning `kingdom.json`; `result.subagent_stats.by_type` counts apprentices per session.
- Agents start in the background by default, so one `-p` process can print several `result` lines; the adapter takes the last one.
